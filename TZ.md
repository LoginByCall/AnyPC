## 1. Цель и границы

**Цель.** Оператор с ПК-А видит рабочий стол ПК-Б и управляет им мышью и клавиатурой в реальном времени. Оба ПК — Windows 11, каждый за своим NAT, белых IP и проброса портов нет.

**В объёме (MVP → v1):**
- просмотр экрана и управление мышью/клавиатурой;
- подключение по ID хоста + пароль / подтверждение на хосте;
- прямое P2P-соединение с откатом на ретранслятор;
- сквозное шифрование;
- буфер обмена (текст), передача файлов, несколько мониторов;
- работа с экраном блокировки и окнами UAC (режим службы);
- автозапуск хоста и подключение без присутствия человека (unattended).

**Вне объёма:** macOS/Linux/мобильные клиенты, звук, удалённая печать, запись сессий, адресная книга, многопользовательские организации, VPN-режим, биллинг. Добавляются отдельным ТЗ.

## 3. Термины

- **Хост** — управляемый ПК (ПК-Б), на нём агент `anypc-host`.
- **Клиент** — управляющая сторона (ПК-А).
- **Сервер** — VPS: сигнализация + STUN/TURN + раздача веб-клиента.
- **ID** — 9-значный номер хоста, выдаётся сервером, привязан к ключу хоста.
- **Сессия** — одно подключение клиента к хосту.

## 4. Архитектура (рекомендуемая)

```
 ПК-А (клиент)                     VPS (белый IP)                    ПК-Б (хост)
┌──────────────┐  WSS/443   ┌─────────────────────────┐  WSS/443  ┌───────────────────┐
│ Edge/Chrome  │◄──────────►│ anypc-server (сигнализ.)│◄─────────►│ anypc-host        │
│ веб-клиент   │            │ coturn (STUN/TURN)      │           │  служба (SYSTEM)  │
│ (WebRTC)     │            │ Caddy (TLS, статика)    │           │  + helper в сессии│
└──────┬───────┘            └────────────┬────────────┘           └─────────┬─────────┘
       │      P2P (ICE, UDP)  — основной путь                               │
       └────────────────────────────────────────────────────────────────────┘
       │      TURN UDP/3478, TURN-TLS/443 — откат                           │
       └──────────────────────►  coturn  ◄──────────────────────────────────┘
```

**Транспорт — WebRTC.** Он даёт готовыми: обход NAT (ICE/STUN/TURN), шифрование (DTLS-SRTP), видеотракт с управлением битрейтом, каналы данных для ввода/файлов. Собственный протокол обхода NAT и шифрования **не писать**.

| Узел | Дефолт | Почему |
|---|---|---|
| Хост-агент | Go + Pion WebRTC | зрелый WebRTC без C++-сборки libwebrtc, один бинарник |
| Захват экрана | DXGI Desktop Duplication | минимальная задержка, курсор, работа на Winlogon-рабочем столе из SYSTEM |
| Кодирование | H.264: аппаратный (NVENC/QSV/AMF через Media Foundation) → программный OpenH264 | H.264 аппаратно декодируется любым браузером |
| Клиент | веб-страница в Edge/Chrome | Edge есть в Win11 → на ПК-А ничего не ставится; декодер и WebRTC — браузерные |
| Сигнализация | Go, WebSocket, JSON | тот же язык, что хост |
| STUN/TURN | coturn | стандарт, не пишем |
| TLS | Let's Encrypt через `autocert` внутри anypc-server | на один процесс меньше, чем с Caddy (NOTIFY, Э0) |
| Развёртывание сервера | `deploy/setup.sh` (apt coturn + systemd) | одна команда, без Docker: на VPS 1 ГБ RAM / 10 ГБ диска |

Захват и кодирование — на этапе Э0 spike сравнить: (a) свой DXGI + Media Foundation через COM из Go; (b) подпроцесс `ffmpeg -f ddagrab` + `h264_mf`/`h264_nvenc`. Критерий — REQ-N-02 и REQ-N-04. Результат → ADR-001.

**Ограничение веб-клиента:** Ctrl+Alt+Del и часть системных сочетаний браузер не перехватывает → кнопки «Ctrl+Alt+Del», «Win», «Alt+Tab» на панели; в полноэкранном режиме — Keyboard Lock API. Если это неприемлемо — Вопрос 1.

## 7. Контракты

Внутренние до первого развёртывания на оба ПК; после — внешние (A2 #9). Каждое сообщение несёт поле `"v": 1`.

**Сигнализация (WSS `/ws`, JSON):**

| Сообщение | Направление | Назначение |
|---|---|---|
| `register {pubkey, sig}` → `registered {id}` | хост ↔ сервер | выдача/подтверждение ID; подпись challenge ключом хоста |
| `connect {target_id}` | клиент → сервер | запрос сессии |
| `offer / answer {sdp}` | через сервер | обмен SDP |
| `ice {candidate}` | через сервер | trickle ICE |
| `hello {id, ice}` | сервер → стороны | ID и ICE-серверы с временными TURN-учётками (coturn `use-auth-secret`, TTL 24 ч: coturn проверяет срок и при refresh аллокации) |
| `bye {reason}` | любые | закрытие |
| `error {code, msg}` | сервер → стороны | коды фиксированы в `docs/protocol.md` |

**Каналы данных WebRTC:**

| Канал | Режим | Содержимое |
|---|---|---|
| `auth` | надёжный | PAKE-рукопожатие (REQ-S-02) — до него остальные каналы и видео не открываются |
| `input` | надёжный, упорядоченный | мышь (абс. координаты 0..65535 по монитору), клавиши (скан-код + extended + down/up) |
| `ctl` | надёжный | выбор монитора, качество, буфер обмена, спецклавиши, статистика |
| `file` | надёжный, отдельный на файл | метаданные, чанки 64 КБ, SHA-256 в конце |

Формат кадров — в `docs/protocol.md`, с тестами сериализации.

## 8. Безопасность — **требует ревью человеком (A13, A2 #10)**

| ID | Требование | Критерий приёмки |
|---|---|---|
| REQ-S-01 | Медиа и данные шифруются сквозным образом (DTLS-SRTP / DTLS-SCTP); сервер и TURN видят только шифротекст | дамп трафика на VPS не содержит кадров и ввода в открытом виде |
| REQ-S-02 | Аутентификация паролем — внутри зашифрованного канала через PAKE (CPace/SPAKE2 из проверенной библиотеки), с привязкой к DTLS-отпечаткам обеих сторон. Сервер **никогда** не получает пароль или его хэш | тест: подмена SDP-отпечатка на сервере (MITM) → аутентификация не проходит |
| REQ-S-03 | Постоянный пароль ≥ 10 символов, хранится на хосте как Argon2id-верификатор, файл доступен только SYSTEM | проверка ACL файла; пароль не находится поиском по диску |
| REQ-S-04 | Защита от перебора: 5 неудач → блокировка ID для этого клиента/IP на 1 мин, далее удвоение до 1 ч | автотест на 20 попыток |
| REQ-S-05 | Ключ хоста (Ed25519) не покидает хост; клиент запоминает отпечаток хоста при первом входе (TOFU) и предупреждает при смене | тест смены ключа → предупреждение |
| REQ-S-06 | Сигнализация только по TLS 1.2+; TURN-учётки временные; секреты сервера — из переменных окружения, не в git | `git grep` по секретам пуст |
| REQ-S-07 | Ввод от клиента валидируется (диапазоны координат, известные скан-коды, размер сообщений ≤ 64 КБ) | фаззинг-тест парсера 10 мин без паники |
| REQ-S-08 | Скрытая сессия невозможна: без REQ-F-15 сессия не стартует | тест: плашка не создана → сессия отклоняется |
| REQ-S-09 | Сервер не хранит ПДн сверх ID, публичного ключа и IP последнего входа; журнал сервера — без содержимого сессий | ревью схемы хранения |

Не проектировать собственную криптографию. Конкретная PAKE-библиотека — ADR + ASK #10.

## 9. Особенности Windows (обязательны к учёту)

- **Изоляция сессии 0:** служба (SYSTEM) не видит рабочий стол пользователя. Служба запускает helper в активной консольной сессии (`WTSGetActiveConsoleSessionId` + `CreateProcessAsUser` с токеном SYSTEM) и перезапускает его при смене сессии/входе/выходе (`WTS_SESSION_*`).
- **Рабочие столы:** helper следит за `Default` ↔ `Winlogon` (UAC, Ctrl+Alt+Del, блокировка) и переключает захват и ввод (`OpenInputDesktop` + `SetThreadDesktop`).
- **Ввод:** `SendInput` со скан-кодами (`KEYEVENTF_SCANCODE`), абсолютные координаты по виртуальному экрану. Ввод в окна с повышенными правами — только из helper под SYSTEM (UIPI).
- **Ctrl+Alt+Del:** `SendSAS` из службы; требует политики `SoftwareSASGeneration` — на Home нет gpedit, установщик пишет значение в `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System` и сообщает об этом. `[ПРЕДПОЛОЖЕНИЕ: работает на Home — проверить в Э3]`
- **DPI:** процесс helper — Per-Monitor DPI Aware v2.
- **DXGI:** обработка `DXGI_ERROR_ACCESS_LOST` (смена режима, UAC) — пересоздание дубликатора без разрыва сессии.
- **Брандмауэр:** установщик добавляет правило для исполняемого файла; удаление — убирает.
- **Defender/SmartScreen:** неподписанный инструмент удалённого доступа вероятно будет помечен (PUA). MVP — исключение вручную на двух ПК; подпись кода — Вопрос 3.
- **Без драйверов ядра:** не использовать драйверы режима ядра (виртуальный дисплей, фильтры ввода, mirror-драйвер) — им подпись Microsoft обязательна, без неё не загрузятся. Всё делается из пользовательского режима и службы.
- **Неподписанный exe запускается на любом ПК** ценой предупреждений: SmartScreen («Подробнее → Выполнить в любом случае», только для скачанных файлов), UAC «Издатель: неизвестен». Исключение — включённый Smart App Control: блокирует без обхода, нужно отключать. Ложные срабатывания Defender — отправка файла на анализ Microsoft (бесплатно).
- **Подпись (дефолт):** собственный самоподписанный сертификат; корневой сертификат ставится в `Trusted Root` + `Trusted Publishers` только на двух ПК; подпись в CI через `osslsigncode`; закрытый ключ — вне git, только на машине разработчика `[требует ревью человеком, A2 #10]`.

- **эмуляция NAT** через network namespaces + iptables: full-cone ↔ full-cone → ожидается P2P; symmetric (`MASQUERADE --random`) ↔ symmetric → ожидается TURN. Проверка типа выбранной пары кандидатов;
- деградация канала через `tc netem` (1 Мбит/с, 5 % потерь, 100 мс) → REQ-N-03, 06;
- MITM-тест REQ-S-02, перебор REQ-S-04, фаззинг REQ-S-07.

**V1 (Windows, GitHub Actions `windows-latest`):** сборка, тест захвата DXGI на виртуальном дисплее, тест преобразования координат/DPI, тест инъекции ввода в тестовое окно.

**Автоматический замер задержки (перевод V2→V1):** хост ставит метку времени захвата (RTP header extension `abs-capture-time`), клиент — время отрисовки кадра (`requestVideoFrameCallback`), часы синхронизируются пингом по `ctl`. Метрика пишется в статистику REQ-F-17. Калибруется один раз Измерением #2.

**V3 (человек, два ПК):** сценарии приёмки каждого этапа — чек-лист в `docs/acceptance.md`, результаты в `LOGBOOK.md`.

Таблица трассировки `требование → критерий → тест → статус` ведётся в `docs/trace.md`, начиная с Э1. Статус пишется по формату A11: требование «подтверждено» только при достигнутом уровне.

## 13. Риски

| Риск | Влияние | Митигация / триггер отказа |
|---|---|---|
| Оба NAT симметричные/CGNAT | весь трафик через VPS: задержка + трафик VPS | TURN заложен; VPS выбирать ближе к обоим ПК; лимит трафика тарифа проверить |
| Задержка браузерного клиента > REQ-N-02 | неудобное управление | Э0 замер; при провале — нативный клиент на том же Pion (ADR, NOTIFY) |
| Defender удаляет агент как RAT | хост не запускается | исключение / подпись кода (Вопрос 3) |
| Secure desktop/UAC не захватывается | нельзя управлять при блокировке | Э3 вынесен отдельно; fallback — работать только в пользовательской сессии |
| Использование как инструмента скрытого доступа | правовой и репутационный риск | REQ-F-15, REQ-S-08 — неотключаемы |
| Уже есть готовые решения | работа может не окупиться | см. §15 |
