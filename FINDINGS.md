# Ключевые находки проекта AnyPC

Что выяснено замером, отладкой или ревью и не очевидно из кода. Формат: утверждение → условия → доказательство.
`[вывод]` — выведено, не измерено; `[ПРЕДПОЛОЖЕНИЕ]` — не проверено. Новые находки дописываются сюда сразу,

## Видео: передача и адаптация

- **Кадр, отправленный пачкой, теряется на приёмнике, а не в сети.** Пачка 400 × 1,2 КБ Мак → Linux по гигабитной
  LAN: буфер приёма 208 КБ (по умолчанию) — потери 20–30 %; буфер 4 МБ — 0 %; та же пачка в темпе 10 Мбит/с
  при буфере 208 КБ — 0 %. Пинг при этом 0 % потерь. Условия: UDP, приёмник не успевает вычитать сотню пакетов.
  Доказательство: LOGBOOK 2026-11-10. Следствие: нужен темп отправки (agent/pace.go).
- **Ложные потери обрушивают поток.** Контроллер (rate.go) видит 11–20 % потерь и режет 4000 → 300 кбит/с, в режиме
  «Качество» вместе с ним падает частота до 5 к/с; на 300 кбит/с новый экран текста дорисовывается до 40 дБ
  3,8–6,7 с. Это и есть «фризы и обновление картинки 7–8 с» на Маке (отчёт владельца 2026-11-10, журнал хоста).
- **Пейсер pion (gcc.LeakyBucketPacer) не решает задачу:** копит бюджет в простое (`budget` от последней отправки)
  и выпускает следующий кадр той же пачкой; очередь без предела. Доказательство: исходник interceptor v0.1.51.
- **Пейсер должен стоять выше TWCC/GCC** в цепочке интерсепторов (регистрироваться последним), иначе задержка
  пейсинга попадёт в замер задержки сети и GCC увидит ложную перегрузку. `[вывод]` из устройства pion Chain.
- **Рост после падения был слишком медленным:** +30 % раз в 20 с хорошего канала → 300 → 4000 кбит/с больше 3 мин.
  Пауза нужна только ffmpeg (шаг = перезапуск); кодеру в процессе — 3 с (TestRateFast).
- **GCC на чистой LAN занижал оценку до 300–400 кбит/с при 0 % потерь** (H.264, v0.1.13) — пачки кадров дают
  разброс задержки прихода. `[вывод]`: лечится тем же темпом отправки.

## Видео: кодеки (замеры на тексте 1080p, LOGBOOK 2026-11-09/10; повтор — agent/vp9bench.sh)

- **x264 ABR с IDR раз в секунду портит статику:** PSNR пилой 21–34 дБ на 500 кбит/с. CRF 20 + потолок VBV без
  периодических IDR — 31 → 61 дБ монотонно, статика 16 кбит/с.
- **intra-refresh x264 хуже:** каждая волна перекодирует хорошую картинку при QP 39–44 (45 → 30 дБ каждые 3 с).
- **VP9 (libvpx, screen) лучше x264 на тексте и движении:** дорисовка вдвое быстрее, на движении +1 дБ при 72 %
  битрейта; CPU ≈ 1 ядро на 1080p30 (Linux 16 ядер 3,6 мс/кадр, Мак Xeon 2012 7,0 мс/кадр). OpenH264 упирается
  в 44 дБ; SVT-AV1 2.3.0 из ffmpeg в CBR не выдал поток.
- **libvpx в режиме CQ не держит размер кадра:** смена картинки — кадр 110–175 КБ (15–42 средних), на статике
  периодические кадры до 175 КБ. VP9E_SET_MAX_INTER_BITRATE_PCT в CQ не действует (замер). Строго держит только CBR.
- **libvpx CBR с MinQ 2 тратит 1–1,3 Мбит/с на статичном экране** (дорисовывает до ~60 дБ бесконечно);
  MinQ 10 — 80 кбит/с и потолок ≈ 50 дБ, MinQ 16 — 25 кбит/с и ≈ 47 дБ. Выбрано: CBR, MinQ 10, AQ 3,
  ключевой ≤ 300 мс потока (как libwebrtc). Наибольший кадр 28 КБ, 40 дБ за 0,4 с на 4 Мбит/с.
- **Пропуск кадров кодером (rc_dropframe_thresh) на смене текста только замедляет дорисовку** — выключен.
- **В режиме «Качество» источник VP9 застревал на 5 к/с** после смены профиля: ffmpeg запускался с частотой
  rate.fps(); исправлено — источник всегда на полной частоте, прореживает streamVP9.
- **Курсор в кадре делает статику «движущейся».** Курсор отдельно по ctl: при движении одной мыши видео статично.

## Клиент и вход

- **«Запомнить пароль» не срабатывал при повторном входе, и с именем это выглядело как «неверное имя или пароль».**
  Клиент стирает пароль из поля при входе («ok»), а запомненный подставлял только на ввод ID (`oninput`). После
  «Разорвать» ID в поле остаётся — повторное «Подключиться» уходило с пустым паролем: «fail» хоста (и лишняя неудача
  в счётчике перебора), с именем — текст «неверное имя или пароль». Исправлено: после сессии запомненный пароль
  подставляется снова, без пароля вход не начинается. Доказательство: TestBrowserUsers (refill/again/nopw), до правки —
  `again=Error: wrong name or password`. Доска владельца 2026-11-11, обе карточки ToDo.
- **Записи по имени не действуют не только при галочке «Спрашивать»,** но и когда у записи по умолчанию нет TOTP
  (`codeModeLocked`: `Users[0].TOTP == ""`) — свой TOTP записи не помогает. Ответ хоста тот же «fail» (REQ-S-21/23),
  клиент пишет «неверное имя или пароль» — с 2026-11-11 с подсказкой про эти два случая. Источник: app/config.go codeModeLocked, TZ.md REQ-S-23.

## Платформы

- **Windows: DXGI_ERROR_ACCESS_LOST (887a0026)** через секунды после старта (UAC, блокировка, полноэкранное окно) —
  захват надо перезапускать; регрессия TestCaptureRestart.
- **macOS avfoundation не слушает -framerate для экрана:** ~420 к/с с ложными метками, серый кадр у клиента; нужен
  фильтр fps. Экран Мака в точках, Retina — пикселей вдвое больше.
- **macOS: системный курсор не сравнить по объекту** (NSCursor.currentSystemCursor — копия) — форма не определяется.
- **macOS: сетевые e2e-тесты агента на en0 плавают** (ICE висит в UDP WriteTo, и на v0.1.5). `[ПРЕДПОЛОЖЕНИЕ]`:
  LuLu держит пакеты нового неподписанного бинарника до ответа на запрос. Не проверено.
- **macOS: процесс, запущенный по ssh, не получит «Запись экрана»** (разрешение выдано Терминалу) — хост на Маке
  перезапускает только владелец из Терминала. `[вывод]`
- **Wayland: курсор рисует портал** (cursor_mode 2), отдельно его не отдать.

## Сборка и выпуск

- **libvpx для Windows требует mingw g++** (vp9/ratectrl_rtc.cc — C++); у configure нет `--cross`, префикс —
  переменной CROSS; mingw-libvpx тянет winpthreads → `-lpthread` на всех платформах, кроме darwin.
- **На Маке ld берёт libvpx.dylib, если она рядом с .a** (Homebrew) — в каталоге lib только libvpx.a; build.sh
  проверяет otool -L.
- **Статический Linux-бинарник с cgo:** `-tags netgo,osusergo -extldflags -static`, иначе glibc getaddrinfo.
- **Тег, уже отправленный на GitHub, перенести нельзя** (классификатор) — новый номер выпуска.
- **Каждый выпуск: MIN_VERSION в deploy/setup.sh = версии тега** в том же коммите, иначе publish.sh откажет.
- **zsh не разбивает строку переменной на аргументы** (`./bench.sh $cfg`) и понимает `$F:t` как модификатор —
  скрипты стенда гонять через bash.
- **GStreamer x264enc tune=zerolatency режет кадр на слайсы по числу потоков** (176 слайсов на 10 кадров), а мы ставим
  длительность сэмпла на каждый слайс: браузер показывает верхнюю полосу кадра и вертикальные полосы ниже (Wayland-хост,
  2026-11-10). Нужно `sliced-threads=false`, как `-x264-params sliced-threads=0` у ffmpeg. Тест TestGstTail.
- **Захват на Wayland (portal_linux.go) не смотрел на Cap.VP9** — всегда H.264; кодер VP9 в процессе ждал Y4M → чёрный
  экран при «Турбо». Новый тип захвата — проверять обе ветки Cap (H.264 и VP9).
- **Любая правка встроенного скрипта ui/index.html (даже комментария) ломает хэш в CSP** — браузер молча не запускает
  скрипт, браузерные тесты падают с пустым результатом. Новый хэш печатает `go test ./ui` (TestCSPHash) — гонять
  `go test ./...`, а не только ./agent.
- **Текст ошибки, который присылает хост, — на языке хоста** (2026-11-10): отказ «только просмотр» при перетаскивании файла
  показывался по-русски в английском клиенте. Клиент проверяет режим сам и пишет из своего словаря; текст хоста — только
  для старых клиентов. Новые сообщения хоста клиенту — кодом, не фразой. Тест TestBrowserView.

  новый CreateSession; при «Отмене» в окне GNOME окно появится снова. На GNOME 50 бывает и «Session creation inhibited»

- **2026-11-13 Сборка из тега не байт-в-байт** (v0.1.23, пересборка для AnyPC-macos в отдельном рабочем дереве): AnyPC.exe и
  AnyPC-linux-amd64 отличаются от выложенных на 59 байт, размер тот же. Отличается только action ID в заголовке build ID
  (`go tool buildid`: первые две части разные, content ID — последние две — одинаковые), то есть код и данные совпадают, а хэш
  входов зависит от каталога сборки, несмотря на -trimpath. Следствие: сверка «пересобрал из тега — сумма та же» не работает;
  сверять `go tool buildid` (content ID) или собирать в одном и том же пути. В SHA256SUMS выкладки взяты прежние строки и
  новая строка AnyPC-macos.
