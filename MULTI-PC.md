# Концепт «Мои ПК»: AnyDesk + Synergy + LocalSend в одной программе

Статус: маршрут A утверждён владельцем 2026-11-13. Решения по нему — в «Лог решений» TZ.md.

## Идея владельца (дословно, 2026-11-13)

> (1) можно использовать для разового подключения (как AnyDesk - помочь в настройке ПК); (2) можно использовать для работы на нескольких ПК одновременно (Synergy - указываешь на каком ты сейчас ПК и он мастер); (3) можно пересылать файлы другим (как гибрид идентификации адресата по ID и отправки как в LocalSend); можно как в (2), но если отошёл с ноутбуком в другую комнату или уехал, то назначаешь ноутбук мастером переключаешься между несколькими ПК как между рабочими столами (принцип AnyDesk/AnyPC). Все переключения/связки этихвариантов должны быть очень простыми и быстрыми (буквально в 1 клик) без переподключения/разрыва связи.

## Сценарии

| # | Сценарий | Что видит человек | Есть сейчас |
|---|---|---|---|
| С1 | Помощь (разово) | ID + одноразовый код, «Разрешить» на той стороне | да (v0.1.24) |
| С2 | Рядом стоящие ПК | один комплект мыши и клавиатуры: курсор уходит за край экрана на соседний ПК; буфер обмена общий | нет |
| С3 | Файл другому | ввёл ID или выбрал соседа в сети → «Отправить» → у получателя «Принять» | передача файлов есть только внутри сессии |
| С4 | Ушёл с ноутбуком | ноутбук — мастер; остальные ПК — как рабочие столы с картинкой, переключение одним щелчком или клавишами | одна сессия = одно окно, переключение — заново подключаться |

## Единая модель

1. **«Мои ПК» — доверенная связка.** ПК объединяются один раз: пароль + TOTP, затем ключ («Доверять этому ПК», карточка Backlog, решение владельца «доверять + TOTP»). Дальше ПК связки соединяются без ввода пароля. Чужие ПК (С1, С3 вне связки) работают как сейчас: код или пароль и подтверждение.
2. **Одно постоянное соединение на пару ПК, пока оба в сети.** Режимы — это каналы внутри него, и они включаются без нового соединения:
   - ввод, буфер обмена, файлы — каналы данных, есть уже сейчас;
   - картинка — видеодорожка: включается (С4) или отключается (С2) пересогласованием внутри того же соединения. Смена «просмотр ↔ управление» без разрыва уже сделана так же (REQ-F-26).
3. **Мастер** — ПК, мышью и клавиатурой которого сейчас пользуются. Назначается щелчком «Работаю отсюда» или сам: последний ПК, где тронули мышь или клавиатуру `[ПРЕДПОЛОЖЕНИЕ: проверить, не мешает ли это в С2]`.
4. **Режим цели выбирается сам или вручную одним щелчком** (решение владельца 2026-11-13: ручной выбор «рядом / картинкой» у каждого соседа главнее автоматики и держится, пока его не снимут). Автоматика:
   - ПК в той же сети и стоит в раскладке экранов → С2 (без картинки);
   - иначе → С4 (с картинкой).
   - Ушёл с ноутбуком: сеть сменилась, и соседи переходят в С4 без действий человека.
5. **Переключение целей в С4** — как рабочие столы: клавиши (например, Ctrl+Alt+→) или щелчок по миниатюре. Соединения тёплые, поэтому показывается только видео другой цели.

## Маршрут (по убыванию риска)

1. **Вход по ключу** («доверять» + TOTP) — основа связки, нужен и сам по себе. Одна сессия.
2. **Разведка перехвата ввода** (1 сессия, код выбрасывается): Wayland-портал на GNOME владельца, CGEventTap на Маке, хук Windows. Не выходит на Wayland → С2 на Wayland-мастере не делаем, только С4. Это главный риск.
   - 2026-11-13 Wayland (GNOME 50): **работает** — барьер на краю, захват, Esc-отпуск, задержка 0,17 мс (FINDINGS). Мак (CGEventTap) и Windows (хуки) — не проверены.
3. **С4: «Мои ПК» и переключение одним щелчком** — больше всего готового и самая ценная часть, если ты уехал.
4. **С2: край экрана** — после разведки.
5. **С3: «Отправить файл» по ID и соседу в сети.** Совместимость с протоколом LocalSend (отправка на телефон) — по запросу, сейчас не закладываем.

## Критерии приёмки (черновик, `[ПРЕДПОЛОЖЕНИЕ]` — уточнить с владельцем)

- С4: переключение на другой ПК связки — картинка ≤ 1 с; соединение не рвётся (без нового входа).
- С2: переход курсора за край в одной сети — задержка ввода ≤ 20 мс (медиана), буфер обмена ≤ 1 с.
- Смена режима С2 ↔ С4 — без разрыва, ≤ 1 с; сама (смена сети) или одним щелчком у соседа.
- С3: отправка по ID — получатель видит «Принять» ≤ 3 с; вне связки без «Принять» файл не записывается.

## Безопасность

- Связка = постоянное право управления. Поэтому:
  - вход в связку только с паролем и TOTP;
  - ключ отзывается из окна хоста;
  - плашка сессии видна всегда, в том числе в С2.
- ТЗ меняется (протокол, A2 #9–10): каналы в постоянном соединении, вход по ключу. Каждый этап — через ASK.
